# Screen Pattern: Trust Entry

> Overrides `MASTER.md` for an entry screen that must establish purpose, trust, and route users into the primary AI workspace.

---

## Section Order

1. Hero or first panel with literal product category and primary task.
2. Live preview, screenshot, or compact demo of the actual workspace.
3. Trust signals: data handling, source quality, review controls, security posture.
4. How it works: Input -> AI processing -> Evidence -> Action.
5. Primary CTA to open the workspace.

---

## Copy Direction

- Headline should name the product category or task, not an internal codename.
- Supporting copy should explain what users provide, what AI does, and how output can be verified.
- Primary CTA should name the action, such as `Open Workspace`, `Start Analysis`, or `Review Results`.

---

## Trust Signals

- Data handling summary.
- Model/provider boundary when relevant.
- Evidence or source policy.
- Human review requirement for consequential actions.
- Health/status signal if the product depends on live services.

---

## Visual Restraint

- Credibility is more important than spectacle.
- The preview should show the real task surface, not decorative abstraction.
- Avoid visuals that make the product look like an ad banner.

---

## Mobile

- Stack content vertically.
- Keep the primary CTA reachable.
- Avoid nested horizontal scrolling inside the main content.
